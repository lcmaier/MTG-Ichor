A Copy Is a Snapshot

One Cytoshape resolution walked through the code as merged, from the CR 707.4 choice to the layer 1a row it registers — then the row read back twice, once for the copy itself and once for a bystander whose power the copy now changes. Every read of game state is labelled by when it reads: the board as it is now, or the frozen values a copy captured at some earlier instant. The whole phase is an argument that those two are different, and the traces are where the difference is visible.

The map

CR 613.2c is the sentence the whole design hangs on: “After all rules and effects in layer 1 have been applied, the object’s characteristics are its copiable values.” Copiable values are the output of layer 1, not an input to it. So the capture is the existing frame-cache entry point at the existing ceiling, and a copy effect is one row in a layer the walk already visits and that has, until now, never contained anything.

Two things the map cannot show and the traces will. The capture happens once, at step 12 of trace A, and is never revisited — every later read in traces B, C and D is a clone out of a box, not a recomputation. And the row alone makes the copy have an ability; it takes a second, derived row to make that ability do anything, which is the whole of trace C.

B · Reading the copy back

The row exists; now something asks what the Test Creature is. Every arrow below is one compute_characteristics call, and the point of the trace is which steps read the board and which read the box.

  1. 1get_effective_power(test_creature)oracle/characteristics.rs:238board

    Every characteristics query routes here. The layer-system invariant, unchanged by this phase.

  2. 2compute_to_ceiling(id, 10, cache)layers/compute.rs:181board

    Seeds the frame from card_data — the printed 1/1 Test Creature — plus the entity’s controller and CR 302.6 clock.

  3. 3LAYER_ORDER[0] = Layer1Copylayers/compute.rs · the layer loopboard

    A slot the walk has always visited and that has always been empty. This is the first phase in which rows_in_layer returns anything here.

  4. 4effect_applies_tolayers/compute.rsboard

    AffectedSet::Fixed, so this is an id comparison against the vector CR 611.2c locked at step 13 of trace A. No filter is resolved and no other object’s frame is asked for.

  5. 5static_ability_still_existslayers/compute.rs:240—

    Returns true immediately: EffectOrigin::Resolution. CR 613.7b — a resolution already happened and there is no ability to go looking for. No frame is computed, which is why a copy row costs nothing beyond its own apply.

  6. 6apply_modification → values.apply_to(chars)layers/compute.rs:1090 → copy.rs:123capture

    The one line this phase adds to the hot path. Ten fields overwritten from the box; controller and control_since_turn untouched, because they are not in it. After this line the frame is a Colossus, and every later layer modifies a Colossus.

  7. 7layers 2–7layers/compute.rs · the same loopboard

    A Layer 7c pump registered on the Test Creature before the copy still applies, and applies to 5/5. This is CR 707.4’s “doesn’t change any noncopy effects presently affecting the permanent”, and it is free because layers 2–7 never learned that layer 1 exists.

  8. 8cda::apply_intrinsic_cdaslayers/cda.rscapture

    Reads chars.abilities, which since step 6 is the captured list with each is_characteristic_defining carried verbatim. CR 604.3a(2)’s third clause — a copied CDA is still a CDA — is implemented by not writing anything. A Layer 6 grant is the opposite and must clear the flag.

Step 5 is where the performance argument lives. layers-architecture.md §12 measured the CR 613.7a existence check, ungated, at 5.2× to 8.0× — because a static-ability row makes the walk compute its source’s frame. A copy row is Resolution, so it never does. What CV-1 adds to Frames/walk is not the copy row; it is the derived rows of trace C, which are static-ability rows like any other.

    Back to 3. Teardown happened without a teardown: “registry membership is not effect existence” is doing the work, and it is why leg 2 needed no removal path and no reconciliation at a mutation chokepoint.

What this leaves. The superseded derived row is inert but present until CR 514.2 cleanup. Harmless for a turn-bounded copy, which is all CV-1 ships; with Duration::Indefinite — CV-1b, blocked on CR 400.7 — re-copies would accumulate rows without bound. Recorded in codebase-state.md’s Deferred Migrations as CV-1b’s prerequisite rather than fixed here, because the fix wants the same subject-keyed teardown item 10 owes every pump spell.

The two gates

Both are the same shape, and the shape is the finding worth keeping: a fast-path gate must be derived from the same place its sweep reads. Each sweep reads the effective ability list; each gate reads sources of ability. Every new route to that list is a new leg on every such gate — and the number of gates grows too, which is what CV-1 discovered by finding RS-1’s.

GateLeg 1 · printedLeg 2 · grantedLeg 3 · copiedStill missing

The copied legs are summary flags rather than inserts into the two *_ability_sources sets, and the reason is those sets’ own doc comments: each is “a set rather than a count, so it cannot drift”, and each is cleared only at cleanup_zone_state. A copy row can expire with no zone change, so an insert would leave the set high. Drifting high is the safe direction — a wasted walk, never a wrong answer — but quietly falsifying that sentence is worse than one more field, and the summary is recomputed from the rows on every mutation, so it cannot drift at all.

Both flags scan the captured ability bodies, not the presence of a copy row. A copy of a vanilla creature turns neither on, which is what keeps them worth having: a flag that is permanently true buys nothing.
