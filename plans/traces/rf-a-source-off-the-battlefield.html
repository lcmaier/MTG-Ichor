A Source Off the Battlefield

RF let the replacement gather read a static ability where CR 113.6 says it functions — a Colossus in a library, a Nexus of Fate on the stack. The question asked at review was the right one to walk: why does the gather not walk every card in both libraries the moment a Colossus is in one? Three boards, read by read, and the table of what each read consults.

replacement/gather-zone-leg @ ca88adfCR tmnt2026-09-16, at review Authority for the design: plans/archive/replacement-architecture-landed.md, "RF" (evicted from §9), and plans/replacement-architecture.md §3.3 source 2, §11 item 4. Tests: mtgsim/tests/phase_rf_integration_test.rs, and one unit test in gather.rs.

The map

Three boards. The first is the one the review asked about and is deliberately dull — nothing happens to the Colossus — because the cost of a source off the battlefield is paid on the events that cannot touch it, which is almost all of them. The second is the card's own clause end to end. The third is two replacement effects on one card's journey, and the reason the rider moves nothing.

Trace A — a Colossus in a library while a Bolt resolves

Player 0's library holds a Darksteel Colossus somewhere in its sixty cards. Player 1 has a tapland on the battlefield (a printed "enters tapped", the ordinary pooled shape) and resolves Lightning Bolt at a bear. The Colossus's clause watches one kind of event — "would be put into a graveyard" — and this is not it. What does the gather do for the Colossus?

  1. execute_action(DealDamage { source: Bolt, target: bear, amount: 3 }) → apply_replacements builds EntryFrame::new — empty, since a damage event enters nothing — and calls gather. subject = Object(bear), cause = Some(1).
  2. gather, the gate state: replacement_ability_sources = {tapland} (a battlefield object that printed a replacement), zone_replacement_ability_sources = {Colossus → [its printed def]} (filed by create_in_zone at Game::new, where functions_in(clause, printed types, Library) said yes because the clause states SourceInZone(ALL)). The summary registry: unattributed_replacement_zones = EMPTY, any_named_unattributed_replacement = false — no row grants or copies a replacement ability. So has_static_source is true and the sweeps run.
  3. battlefield_ids_ordered board: the bear is not in the printed set and no unattributed row reaches the battlefield → skipped without a walk. The tapland is in the set → one compute_characteristics (a memo hit unless the layer epoch moved), its "enters tapped" pattern is EnterBattlefield and the event is DealDamage → not a candidate. This is RC-2's per-permanent gate, unchanged.
  4. gather, the zone leg, printed list state: one entry. printed_could_apply(Colossus, def) → def_applies: by is None ✓; pattern_watches(ZoneChange { to: Graveyard }, DealDamage) → the match has no arm for that pair → false. No frame is computed. Nothing in the library is touched. The Colossus cost this gather one pattern match.
  5. The named list: any_named_unattributed_replacement is false → the registry rows are not scanned. The zoned list: unattributed_zones.beyond_battlefield() is EMPTY → zone_ids_ordered is never called. This is the step the review asked about: the library is a candidate list only when a Filter-scoped grant or copy row reaches the LIBRARY zone — "cards in libraries have 'if this would …'" — and no registered card makes such a row. The printed leg never walks a zone; it iterates a map whose keys are the cards that printed a clause functioning where they are.
  6. gather, sources 3 and 4 registry: no rows. Candidates: []. The Bolt resolves as it would have before RF.
Why the precheck is exact and not a shortcut. The gather's rule is that a static replacement ability is discovered off the effective list, never a registry (CLAUDE.md). The zone leg keeps that rule — when it reads, it reads the frame — but asks first whether any printed def could apply. Sound because an object's effective replacement defs are its printed ones or fewer: Layer 6 can strip one (Hollow Hands) or grant one, and a granted or copied def reaches the leg through the named or zoned list, never through this map; nothing rewrites a printed def in place, Layer 3 being the route every gate leg leaves open. So a printed def that does not apply has no effective def that could. Asked through def_applies, the same function the effective def is asked through, so the pairing of patterns and events lives once.
Before the review's change, step 4 computed the Colossus's frame on every gather — a one-frame non-member walk, or a memo hit — and found the pattern did not match one function later. Exact, and flat per decision at four seats, but ~150 walks a game at two seats and ~550 at four for nothing. The review's "there has to be a more efficient way" was right, and the way was to ask the printed def first.

Trace B — the same Colossus, second of three, milled

Player 0's library, top down: a 2/2, the Colossus, a 1/1. A spell player 0 controls resolves "mill three cards". CR 701.17a puts the top three into the graveyard; Primitive::Mill proposes them as one batch of three ZoneChange { from: Library, to: Graveyard, cause: Milled } members, top first, and execute_batch_inner decides each member's group against the same board.

  1. resolve_primitive(Mill(3)) reads the top three ids off the library board before anything moves, and calls execute_actions([above, Colossus, below]).
  2. Member above: gather. Battlefield sweep: nothing printed. Zone leg, printed list: printed_could_apply(Colossus, def) → pattern_watches(ZoneChange { to: Graveyard }, ZoneChange { to: Graveyard }) ✓ → set_affects(SourceOnly): source == subject? Colossus ≠ above → false. No frame. Candidates []. Performed: above → graveyard, announced with its LKI-less ZoneChange line.
  3. Member Colossus: printed_could_apply ✓ — same pattern, and now the subject is the source. Only now: compute_characteristics(Colossus) board → membership says NonMember (no row reaches the library) → compute_non_member, a one-frame CDA walk seeded from the card. Its effective abilities: the clause. functions_in(clause, {Artifact, Creature}, Library) → stated_zones reads SourceInZone(ALL) → contains Library ✓. The "as long as" wrapper: settled_holds(SourceInZone(ALL)) ✓. Scope is Existing. def_applies ✓ (the same three checks as step 2, now against the effective def). One candidate.
  4. CR 616.1 loop: one candidate, mandatory → applied without a prompt. apply_rewrite(Instead(ZoneChangeTo { Library, PutIntoLibrary })) → the substitute is ZoneChange { object: Colossus, from: Library, to: Library }; applied = {Colossus's clause}; one rider queued — then = ShuffleLibrary with an Implicit recipient, subject Colossus, source Colossus. Iteration 2 on the substitute: pattern_watches(to: Graveyard, to: Library) → nothing → return.
  5. perform_zone_change(Colossus, Library, Library) board: from == to → Ok(()), nothing moves and nothing is announced. A card put into the zone it is in has not changed zones (CR 400.1's zones are the seven), so there is no ZoneChange line to write; CR 701.24c's "even if … remain in their current zone" is this branch.
  6. Member below: as step 2 — the printed def's subject check fails, no frame, milled. The batch is done: two ZoneChange lines, the Colossus alone in the library.
  7. Riders, after the batch (§4.1a): resolve_rider builds a ResolutionContext { source: Colossus, targets: [Object(Colossus)] } and resolves Atom(ShuffleLibrary, Implicit). resolve_primitive: Implicit → the source's owner, player 0 — "its owner's library" — and one batch of one GameAction::ShuffleLibrary { player: 0 } through execute_actions. gather finds nothing (no pattern watches a shuffle; there is deliberately no arm). perform_action → shuffle_library(0) board → LibraryShuffled { player_id: 0 }. The log reads mill, mill, shuffle: the whole event, then the rest of the instruction.
One event, not a loop that stops. CR 616.1 decides each member against the same board and the batch performs them together; the Colossus's clause replaced its own member and nothing else, and the card below it was milled although it sat under a card that "would be put into a graveyard … instead". The test asserts the graveyard's order (above, below), the library ([Colossus]) and the log's order.

Trace C — a Colossus commander, sacrificed

Player 0's Darksteel Colossus is on the battlefield and is their commander (is_commander). It is sacrificed. Two replacement effects are about this card's journey, and they apply to different events.

  1. change_zone(Colossus, Graveyard, Sacrificed) → gather. CR 903.9b: commander_zone_replacement asks to ∈ {Hand, Library} → Graveyard → none. Battlefield sweep: the Colossus is in replacement_ability_sources → its frame → the clause functions on the battlefield (ALL ∋ Battlefield) → def_applies ✓. One candidate, mandatory.
  2. Iteration 1: apply → substitute ZoneChange { from: Battlefield, to: Library, cause: PutIntoLibrary }, applied = {clause}, the shuffle rider queued.
  3. Iteration 2, on the substitute: commander_zone_replacement now sees to: Library and is_commander → an optional, CR 614.5-exempt candidate (ZoneChangeTo { Command }). The battlefield sweep finds the clause again and CR 614.5 filters it — it is in applied. One candidate, optional → ask_apply_optional_replacement player: player 0, the affected object's controller, says yes. Substitute: ZoneChange { to: Command, cause: CommanderZoneReplacement }. Iteration 3: 903.9b asks to ∈ {Hand, Library} → Command → none; the clause is filtered; return.
  4. perform_zone_change(Colossus, Battlefield, Command) board: the LKI frame is captured (it was a permanent), cleanup_zone_state retires its battlefield registration, the card lands in the command zone and is announced.
  5. The rider: ShuffleLibrary with Implicit → the source's owner, player 0 → shuffle_library(0). The card is in the command zone and the rider does not go looking for it: it shuffles a library, it does not move an object, and that is CR 701.24c — "that library is shuffled even if … an effect causes all of those objects to be moved to another zone". Had the rider been "shuffle it into its owner's library" as a move, it would have pulled the commander out of the command zone 903.9b just put it in.
Why Primitive::ShuffleIntoLibrary stays unbuilt. A spell's "shuffle target card from your graveyard into your library" must move the card and then shuffle; a rider on a substitute must shuffle and must not move. The same words, two contracts, and the rider's is the one this card needs. The spell's is backlog.md §2.5's, one change_zone plus one ShuffleLibrary proposal per target.

What RF changed, trace by trace — and what is still open

A is the answer to the review's question, and it is structural rather than measured: the printed leg iterates a map keyed by the cards that filed themselves, and the only thing that ever walks a zone is a Filter-scoped grant or copy row reaching it. At landing, A cost a frame per gather per Colossus; at review it costs a pattern match, because the printed def can be asked first without losing exactness.

B is the card's clause end to end and the shape of a batch: one event, each member decided against the same board, the substitute a same-zone no-op, the rider after. It is also why "shuffle it into its owner's library" is a substitute plus a rider and not one template.

C is CR 616.1 twice on one card, with two different choosers' questions (one mandatory, one a prompt), and the reason the rider is ShuffleLibrary rather than ShuffleIntoLibrary.

Open, each with a dated line in codebase-state.md: the restriction sweep still visits the battlefield alone and its zone leg is owed against Abrupt Decay (main item 146); Hollow Hands owes the tests that show a strip in hand turning off cycling, channel and the rest, once one of them exists (147). The precheck is the zone leg's alone: the battlefield sweep still computes a frame for every printed source on every gather, and the same argument would let it ask the printed def first — an answer-preserving lever that moves the Layer walks row and so wants its own A/B.
