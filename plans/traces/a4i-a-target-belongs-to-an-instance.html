A Target Belongs to an Instance

A4i made CR 115.3's instance of the word "target" the unit a chosen object is filed under. The review asked two questions the diff cannot answer: why does a function that resolves one effect need a cursor? and how does "another target" stack? Three boards, read by read, and the table of what each read consults.

The rule this page is about. CR 601.2c: "The same target can't be chosen multiple times for any one instance of the word 'target' on the spell. However, if the spell uses the word 'target' in multiple places, the same object or player can be chosen once for each instance of the word 'target' (as long as it fits the targeting criteria)." Everything below is that sentence, and its worked example two lines later: "A spell that says 'Destroy target artifact and target land' can target the same artifact land twice."

The map

Three boards. The first is deliberately the dullest thing the phase can do — one creature, one spell, nothing to choose — because that board is where the instance becomes visible: three atoms that are equal in every field have to reach three different slots, and nothing about the atom says which. The second is the "another target" chain, which is the only shape where an earlier choice constrains a later one. The third is CR 608.2b, whose two rules the one-recipient model could only ask one of.

Four ways a target can fail, and they are four different rules. The diagram carries all of them because telling them apart is most of what the phase does. not offered is CR 601.2c asked before the cast is proposed, so the engine never has to rewind — Decimate's reminder text as a function. rollback is CR 601.2e, for a proposal that got past enumeration and failed validation. handle_fizzle is CR 608.2b's first rule, asked across every instance at once. And proposes nothing is CR 608.2b's second rule, per instance — the one the old model had no shape for, because an atom handed an empty slice does nothing while its siblings resolve normally.

Trace A — three equal atoms, three instances

Board. Player 0 controls one Grizzly Bears (2/2). Seeds of Strength — "Target creature gets +1/+1 until end of turn." printed three times — is in hand, with exactly {G}{W} in the pool.

The card's effect is a Sequence of three Atoms, and the three recipients are structurally equal: Target(Creature, Exactly(1)), three times. That equality is the whole difficulty. Ensoul Artifact also has two equal recipients and is one instance; nothing in the values tells the two cases apart, which is why the card says which it means and why the resolution cannot recover it by comparing.

  1. spell_instances(card) effect tree — no enchant_filter, so the spell ability's effect is walked. An Aura would have stopped one line earlier, and the trace below never reaches it: an Aura spell has no spell ability at all (CR 702.5a — enchant is a static ability on the permanent), so walking abilities for an AbilityType::Spell finds nothing and would announce zero instances. The early return synthesizes the one instance CR 303.4c gives it, from enchant_filter. That is what makes the castability check, the announcement and the CR 608.2b re-check all see the same clause — it was Deferred Migrations item 8 when they did not. collect_instances descends Sequence, pushes each Target/Choose atom's recipient, and skips everything else. Result: three clauses, numbered 0, 1, 2 by position.
  2. every_instance_has_a_choice battlefield — for each clause, has_legal_choices(Creature, n = 1, earlier_targets) scans battlefield_ids_ordered and stops at the first legal candidate. One creature, so all three clauses pass. No feed-forward runs: clause_reads_earlier_instances is false for every clause, so rposition is None and the full enumeration is skipped. The cast is offered.
  3. announce_targets → instance 0 (“instance” is CR 115.3's own word and is the name everywhere — TargetInstance, effect_instances, instance 0. What the review proposed renaming is only the recipient variant: at a call site EffectRecipient::SameInstanceAs(0) reads as “this atom's recipient is instance 0” when it means “this atom reuses the instance declared at 0”.) player — enumerate_legal_selections_excluding returns [bears]. ask_select_recipients sees min == max == 1 == legal.len() and returns the list without asking (CR 102.2 — a fixed count that takes all of the legal recipients is not a choice). earlier_targets.push([bears]).
  4. → instance 1, and → instance 2, identically. validate_targets checks distinctness within each instance, which is vacuous at one target, and each clause's filter never mentions an earlier instance, so choosing the bear again is legal — CR 601.2c's second sentence.
  5. The entry: chosen_targets = [TargetInstance{Target(Creature,1), [bears]}; 3] stack entry. Three instances, each recording its own clause beside its choice, because CR 608.2b has to re-ask the same question this announcement answered.
  6. surviving_targets battlefield — the bear is still a legal creature, so each of the three instances survives whole. announced is true, survived is true, so Some(ChosenTargets).
  7. resolve_effect effect tree — declared = effect_instances(effect) is recomputed here, and this is the invariant the whole design rests on: the effect the resolution walks is the one the announcement walked, because StackEntry.effect was cloned at cast and is never mutated. The two numberings cannot disagree. cursor = 0.
  8. resolve_effect_at → atom 1. instance_of sees a Target, takes ix = 0, bumps the cursor to 1. resolve_primitive is handed ctx.targets.instance(0) = [bears].
  9. → atom 2: ix = 1, cursor 2. → atom 3: ix = 2, cursor 3. Three identical atoms, three different slots — and the slot came from position in the walk, never from the recipient's value.
  10. Three ModifyPowerToughness rows on the same object. 5/5.

This is the answer to "why a cursor". The atom's recipient says what kind of clause it is; it never says which one. The announcement numbered the clauses by pre-order position, so the resolution has to reproduce that numbering, and reproducing it means walking the same tree in the same order while counting declarations. An Instance(ix) atom declares nothing, consumes no number and reads ix directly — which is why the cursor counts declarations, not atoms.

The alternative, and why not. Number the tree once and store the index on each atom. Effect is card data behind an Arc, shared by every copy of the card, so the numbering would have to live on a lowered copy on the StackEntry — a second tree to keep in step with the first. The cursor is the cheap form of the same thing, and it is only safe because of step 7's invariant.

Trace B — "another target", and how the exclusion stacks

Board. Player 0 controls creatures A, B and C, in that timestamp order. Incremental Growth — "Put a +1/+1 counter on target creature, two +1/+1 counters on another target creature, and three +1/+1 counters on a third target creature."

The card writes the exclusion into the criteria, nested:

instance 0:  Target(Creature, Exactly(1))
instance 1:  Target(Permanent(And(ByType(Creature), OtherThanInstance(0))), Exactly(1))
instance 2:  Target(Permanent(And(And(ByType(Creature), OtherThanInstance(0)),
                                  OtherThanInstance(1))), Exactly(1))

Each OtherThanInstance is its own leaf and And conjoins them, so yes, it stacks — instance 2 excludes both earlier choices because it carries both leaves.

  1. every_instance_has_a_choice — feed_until = rposition(clause_reads_earlier_instances) is 2, so the feed-forward runs for instances 0 and 1 and not for 2 (nothing after it reads).
  2. Instance 0: has_legal_choices(Creature, 1, []) → true at A. Then, because 0 < 2, enumerate_legal_selections_excluding runs the full scan and .take(1) pushes [A]. This is the enumeration the A/B priced: a full scan where the check itself short-circuits. See "what is still open".
  3. Instance 1: has_legal_choices(And(Creature, OtherThanInstance(0)), 1, [[A]]). The filter walk reaches OtherThanInstance(0), reads earlier_targets.instance(0) = [A], and answers id != A earlier instances — off the ids, with no frame, exactly as EachOther does, because identity is not a characteristic and no layer can change it. B passes. Push [B].
  4. Instance 2: both leaves read, A and B excluded, C passes. No push — nothing after it reads. The cast is offered.
  5. announce_targets → instance 0: candidates [A, B, C], three options for a count of one, so this is a prompt. The player takes A. earlier_targets.push([A]).
  6. → instance 1: enumerate_legal_selections_excluding now filters A out during enumeration, so the option list is [B, C] — the exclusion shapes the offer rather than rejecting an answer. The player takes B.
  7. → instance 2: both leaves exclude, candidates [C], forced and unasked (CR 102.2). Two prompts for three instances, which is what the test asserts.
  8. surviving_targets — all three legal. announced_targets is built from the entry unfiltered, so an OtherThanInstance re-read at 608.2b sees what CR 601.2c chose and not a half-filtered list. One instance fizzling must not silently legalize another's.
  9. Resolution: cursor 0 → A gets 1, cursor 1 → B gets 2, cursor 2 → C gets 3. Each atom's own clause, each atom's own slot.

Two creatures instead of three, and the spell is never offered. At instance 2, has_legal_choices finds every candidate excluded and returns false, so castable_spells drops the card. That is Incremental Growth's own ruling — "You must choose three different targets in order to cast Incremental Growth" — and it is enforced at enumeration rather than by proposing the cast and rewinding it, because an engine that offers a cast it then rewinds is codebase-state.md item 139's class of defect.

Trace C — CR 608.2b is two rules

Board. Player 0 controls a Seat of the Synod (Artifact Land) that Ensoul Artifact has made a 5/5 artifact creature — so one permanent that is a land and a nonblack creature, which is CR 601.2c's own worked example. Plague Spores — "Destroy target nonblack creature and target land. They can't be regenerated." — is cast, both clauses naming that permanent. Then, in response, it becomes black.

  1. Announcement: instance 0 (nonblack creature) and instance 1 (land) each have exactly one legal choice, so both are forced. The entry holds two instances, both [seat], each with its own clause recorded.
  2. A fixture ChangeColor(Set({Black})) resolves on the Seat battlefield.
  3. surviving_targets battlefield, and this is the payload. Per instance: instance 0's clause is re-asked — is_single_target_legal(Target(nonblack creature), seat) → the layer walk says the Seat is black now → filtered out, instance 0 survives empty. Instance 1's clause — Target(land) → still legal → survives [seat].
  4. Across instances: announced is true (both instances chose something) and survived is true (instance 1 kept a target), so the spell resolves. It is an any, not an all — a spell fails to resolve only when every target of every targeting instance is illegal.
  5. Resolution: the two Restrict atoms declare the instances, then Destroy @ Instance(0) is handed the empty slice and proposes nothing — CR 608.2b's "it won't affect that target" — and Destroy @ Instance(1) is handed [seat] and destroys it.

What the one-recipient model did here. One EffectRecipient for the whole spell and one flat chosen_targets, and any_targets_still_legal answered for the list as a whole. So the board above had one answer for both clauses: either the spell fizzled entirely, or it destroyed the Seat twice. There was no shape in which "destroy target nonblack creature" was skipped and "destroy target land" was not — which is why §2.20 said the rule "cannot be asked", not that it was answered wrongly.

And the same rule inside one instance

Jagged Lightning — "deals 3 damage to each of two target creatures" — is one instance holding two choices. When one of them leaves the battlefield in response, the survivor filter drops it and the other still takes its three. Before A4i this was wrong in the other direction: any_targets_still_legal returned true because one target was legal, and then DealDamage proposed a member for every entry in the flat list, illegal ones included. The per-target half of 608.2b needed no second clause to be wrong.

What this changed, trace by trace — and what is still open

Trace A is the phase in one board: the three slots exist, and they are filled by position. Before A4i the spell had one slot and one prompt, so a card that printed "target creature" three times was indistinguishable from one that printed it once.

Trace B is the shape the design missed until review. §2.20 sized "a recipient per atom (or per instance of 'target')" and named two of CR 601.2c's three lines; the third — the exclusion written into the criteria — is the biggest population the entry counted, 36 cards on o:"another target creature" alone.

Trace C is the rule the old model could not ask. It is also where the phase's live bug came from: on the same board shape, Skullcrack's three atoms are Controller, Controller, Target(Player), and the first-atom rule meant a cast announced no target at all and the damage went nowhere. Four phases of tests missed it because every Skullcrack test stages a ResolutionContext with the target written in by hand — a fixture that writes the answer cannot check the question.

Open, from this review (plans/handoffs/a4i-review.md):

  • The announcement order is the engine's, not the rule's. CR 601.2c fixes no order. The sequential loop is outcome-equivalent today and stops being so the day 601.2c's "must be chosen as a target … the maximum possible number" lands, because that is a global optimum over all instances and a greedy loop cannot see it. No printed card produces one; it is owed as a fixture.
  • The representation. ChosenTargets is still a Vec<Vec<_>> behind a name; a flat buffer with offsets is strictly better, and surviving_targets currently copies the announcement twice.
  • The feed-forward rebuilds where it could subtract. Per-clause enumeration is needed when the clauses' filters differ (Decimate), and the feed-forward only runs when they do not (an "another target" chain) — so the case that costs is exactly the case that could enumerate once.
  • Choice versus target. No registered card uses EffectRecipient::Choose, and the announcement asks one at cast time, which a plain "choose" in an effect's text does not do (CR 608.2c). Inherited from the code A4i replaced, and unsurveyed.
