Every History Read Is a Scan of One Log

Before TR-5h the game's past lived in five stores, each shaped for the reader that asked for it: per-player summaries of counts, a "since your last turn" snapshot, card-type slots, combat rows and targeting rows. TR-5h replaced them with one log, state::history_log: a row per event a card can ask about later, each with its object's frame as the event left it. Every "this turn" count, filter and condition became a scan over those rows, and the layer memo keys a read by what it scanned. This page walks three such reads, and the one that stopped being a scan after TR-5h.

The map

A row (HistoryRow) is one fact about one subject: the record it was written from, its turn, which of the turn's combats had begun, whose event it was, the object it was about as the existence it was (CR 400.7), that object's frame, and the fact (RowFact: a cast, a draw, a gain or a loss of life, an entry, a move, damage dealt, an attack, a block, a removal from combat, a targeting). One writer, advance_history, writes them as each window is dispatched, before anything is matched against it. The rows sit in chunks of sixteen behind Arcs, newest first, so a clone copies one pointer.

Three readers scan them. A span condition or amount (Condition::ThisTurn, LastTurn, SinceYourLastTurn, ThisGame, AmountExpr::History) maps its span to turns and sums the rows (HistoryLog::count). An object fact (ObjectFilter::ThisTurn, ThisCombat) asks the turn's rows of one kind whether they name the object (rows_during). And the turn's targeting rows answer "the first time it became a target this turn". Each lookup notes what it scanned into the layer walk that asked: the turn number, the kind of row, and for "this combat" the combat count.

Trace A — "the first time each turn" and "last turn"

Turn 1, player 0 active. Vengeful Warchief (#21: "Whenever you lose life for the first time each turn, put a +1/+1 counter on this creature") and Paladin of Atonement (#22: "At the beginning of each upkeep, if you lost life last turn, put a +1/+1 counter on this creature") are player 0's. Two Grizzly Bears (#23, #24) are player 1's. Each entry wrote an EnteredBattlefield row (row seq 0 to 3) carrying the permanent's frame.

  1. execute_actions([DealDamage ×2])log one batch, each Bears dealing 1 to player 0: records 4 to 7, a DamageDealt and a LifeChanged for each.
  2. advance_history · place_in_turnstate before the gate, so a card that arrives later in the turn still reads what came before it (Vengeful Warchief's fourth ruling). For each loss, its place among player 0's losses this turn: count_in_turn(0, LifeLossEvents, 1), which is 0, plus this window's losses already placed, plus 1. Record 5 is the first, record 7 the second (note_counted).
  3. push_rowlog row seq 4, DealtDamage { to: Player(0), amount: 1, combat: false }, about #23, its frame a 2/2 under player 1; row seq 5, LostLife(1) for player 0, no object; rows seq 6 and 7 the same for #24.
  4. match_candidateslog the Warchief's arm, "you lose life", against each record: the damage records refuse (seq 24, 26, condition); record 5 matches (seq 25); record 7 is refused by its limit (seq 27): FirstTimeEachTurn asks place_in_turn() == Some(1). One trigger, one counter.
  5. a third hitlog records 11 and 12. Record 12's place is 3, and the limit refuses it (seq 47).
  6. player 1's upkeep · the intervening iflog turn 2. StepBegin: Upkeep is record 24, and Paladin's "each upkeep" arm matches it (seq 112). Its "if" (CR 603.4) is Condition::LastTurn(HistoryCount { You, LifeLost }): history_holds → GameHistory::total → turns_of(LastTurn, 0, 2), which is turn 1 only, the turn before this one whoever's it was → HistoryLog::count. The scan walks back from the newest row, skips turn 2's, and sums each turn 1 row added_to_count admits: the three LostLife(1) rows, 3. At least 1, and a gain would not have offset it (Paladin's first ruling: only whether you lost life, not how much or what you gained): Paladin gets its counter, the "if" asked again the same way as the ability resolves. Asked "this turn", the same count reads turn 2's rows and finds none.
  7. player 0's upkeeplog turn 3, record 43. Last turn is turn 2, which wrote no loss: refused by the intervening if (seq 216).

The one read that is not a scan at this commit. Step 2's count_in_turn reads a tally. TR-5h shipped it as a scan of the turn's rows, once for every counted record, which is quadratic in the turn: a token wipe stacking 8,000 "whenever a creature dies, target player loses 1 life and you gain 1 life" triggers wrote 16,000 life rows and slowed each resolution tenfold. #265 (5c3e943f, 2026-10-20) gave each player's PlayerHistory a TurnTally of the four facts a record is placed among, for the newest turn the log has a row of. It is not a second store: it is summed by the log's own added_to_count, written only by GameHistory::push_row (the one way a row is written; HistoryLog::push is pub(super)), and an earlier turn, or a fact it does not keep, is still read off the log. the_turn_tally_counts_what_the_log_counts holds the two equal.

Trace B — the damage facts

Player 0's Veteran's Banner (#1): "Creatures that dealt combat damage to an opponent this turn get +1/+0", whose affected set is ObjectFilter::ThisTurn(DealtDamageTo { player: Some(Opponent), combat: true }). Grizzly Bears #2 (the raider) and #3 (the pinger) are player 0's; Grizzly Bears #4 is player 1's.

  1. DealDamage(#2 → player 1, combat)log records 4 and 5. Row seq 4: DealtDamage { to: Player(1), amount: 1, combat: true }, its object (#2, epoch 0), its player 0, the source's controller; row seq 5, LostLife(1) for player 1.
  2. bump_layer_epoch_if_read(Rows(DealtDamage))state the Banner's walks noted the damage rows when its filter scanned them, so the write moves the epoch (13 → 14). A drafted frame read that kind, so the window's frames are taken again: the raider walks as a 3/2 (seq 19), and reframe_newest writes it onto row seq 4. The row's frame is the raider as the event left it, the Banner on: the event its own row records turned it on (CR 603.10).
  3. two morelog the pinger deals 1 noncombat damage to player 1 (row seq 6, combat: false); player 1's Bears deals 1 combat damage to player 0 (row seq 8, to: Player(0)). Each moves the epoch the same way.
  4. object_matches_filter · ObjectFilter::ThisTurnlog each creature's walk asks the filter. The existence is the object's current one (or, for an object gone, the one its last known information kept). players_dealt_damage_by(existence, combat_only: true, turn 1, ThisTurn) → rows_during, which notes TurnNumber and Rows(DealtDamage) and keeps turn 1's damage rows; of those, the rows about this existence, their players where the damage was combat. The raider: [1], an opponent of the Banner's controller, 3/2. The pinger: none, its row is noncombat, 2/2. Player 1's Bears: [0], which is "you", 2/2.
  5. a flickerboard the raider is exiled and returned: a new object (CR 400.7), the same id with zone-change epoch 2. Row seq 4 names epoch 0, so nothing matches, and it is a 2/2.

What a damage fact reads, and what a row's frame is for. Neither damage fact reads a frame. DealtDamageTo reads each damage row's object, recipient and combat flag; WasDealtDamage reads the same rows' to (was_dealt_damage_this_turn_reads_the_rows_dealt_to_it). The frame is what a count narrowed by of asks: "creatures with power 3 or greater that died this turn" reads each death row's frame through frame_matches, so a creature pumped to 4/2 before it died counts and its 2/2 graveyard card does not (a_narrowed_count_reads_the_object_as_its_row_kept_it). Before TR-5h no store held a damage fact: the combat rows held attacks, blocks and removals, and TR-5d's first draft would have added a fourth kind to them.

Trace C — the gate, beside the writes that move it

Player 0's Lifted Banner (#21): "Creatures get +1/+0 as long as you've gained life this turn", a static whose condition is Condition::ThisTurn(HistoryCount { You, LifeGainEvents }, AtLeast(1)). Vampire Nighthawk (#22, 2/3, lifelink) and Grizzly Bears (#23) are player 0's. Each step below names the key that moved the epoch, read off a print the probe added to bump_layer_epoch_if_read in a copy of the crate.

  1. compute_characteristics(Nighthawk)log seq 8, epoch 30. The Banner's condition: history_holds → HistoryLog::count(LifeGainEvents, 1..=1), which notes TurnNumber and Rows(Life) into the walk before it scans. No gain row: off, a 2/3. The memo stores the frame with those two keys.
  2. DealDamage(Nighthawk → player 1, 2)log one event with its lifelink gain (CR 702.15b): records 3 (DamageDealt), 4 (player 1, 20 → 18) and 5 (player 0, 20 → 22).
  3. advance_history · the draftframe the rows are drafted with their objects as the window left them, the Nighthawk's from the memo, still a 2/3, and written: row seq 3 DealtDamage, row seq 4 LostLife(2) for player 1, row seq 5 GainedLife(2) for player 0. Kinds written: damage and life. Rows(DealtDamage): no stored frame read it, nothing moves. Rows(Life): the step 1 frame read it at this epoch, so it moves, 30 → 31.
  4. advance_history · the reframeframe the epoch moved, so a frame drafted in step 3 left out the window's own rows. The window's frames are drafted again (seq 21: the Nighthawk at epoch 31, the count now 1, a 3/3), written onto the newest rows by reframe_newest, and the kinds bumped again, 31 → 32. Row seq 3's frame is a 3/3, the Nighthawk as the event left it.
  5. a drawstate player 0 draws: a Drew row. No stored frame read a draw row, so no gated key fires; the one move the epoch makes is not the gate's.
  6. DealDamage(Bears → player 1, 1)state a damage row and a LostLife(1) row for player 1. Rows(Life) moves the epoch (33 → 34), and the reframe moves it again (34 → 35). The key is the kind of row, not whose: player 1's loss throws away a frame that counted player 0's gains, and the next walk answers the same, a 3/2 Bears.
  7. begin_turn · bump_layer_epoch_if_read(TurnNumber)state turn 2 begins: every frame that read the turn number is dropped (35 → 36). The Banner's count is over turn 2's rows now, none, and the Nighthawk is a 2/3 again.

The combat count is the third key: rows_during notes it for a "this combat" question, and a combat beginning bumps it (advance_history's count of CombatBegan), so "creatures that attacked this combat" stands through a draw and falls at the next combat of the turn (CR 500.8's additional combats make that a different question from "this turn"). No board here asks it.

With the note taken out of the lookup. In a copy of the crate, HistoryLog::count without its Rows note: the step 1 frame keys on the turn number alone, step 3 moves nothing, and the next read of the Nighthawk is served from the memo. The debug build's memo audit, which walks fresh against every hit, stops it: "layer memo served a stale frame for #22 at epoch 30", served 2/3 against fresh 3/3. The note lives inside the lookup so that no reader can leave it out; a filter over two facts notes both.

With the reframe skipped. Step 4 removed: row seq 3 keeps the 2/3 drafted in step 3 while the board has a 3/3, and the test fails on exactly that. The build first wrote the rows after their frames and lost this (the archive's "A row's frame sees its own window's rows"); the gate already says when it matters, since a bump of a kind the window wrote moves the epoch only if a frame read it.

What TR-5h changed, and what reads otherwise

Why one log. Five phases had reshaped the history, each for the reader in front of it, and the census TR-5h's design ran found 124 cards counting by what the things were at the time ("for each Zubera that died this turn", "the total mana value of other spells you've cast this turn"), which no number of slots holds and every slot costs every clone. A row per event, kept for the whole game, answers every span a card names, printed or custom, and a new fact is a RowFact variant and a writer arm, never a store. A clone copies one pointer: floor 3 read 2.2 KB lower per clone at TR-5h's close, and a game holds 2.7 to 4.6 KB a turn (fuzz-record.md, TR-5h's block).

What a row is. An event, never the board: its frame is a departure's last known information, or the object as the window left it, the window's own rows included (B's step 2, C's step 4). And a frame, not the store's facts beside it: whether the object was a token, its counters, the owner of an object the store has lost are read from the store by the row's id, which answers for the object now (item 286).

What reads otherwise, at this commit. Three things a card asks about the past are not scans, each on purpose. A record's place in its turn reads the tally #265 keeps with the log (A's callout). "Entered this turn" is the permanent's own fact, its entered turn, read off the permanent or its last known information (ObjectFact::Entered). And the abilities' own gates (what has triggered, been done once, or resolved this turn) stay keyed by ability, as TR-5h's design kept them: rule gates no reader filters. The draw step's count is a field beside the log because no turn can hold it: a turn can have two draw steps (CR 500.8).

Still open (codebase-state.md, "Found by TR-5h"): item 286, above, waiting for the first registered card that narrows a count by token-ness or counters; and item 287, the scenario that names its casts and states the rest as counts. Item 279's other facts (counters, taps, activations, token creations) each join as a variant with their first card.
